# MIA 2027 — Stage 2
Administrative pilot only, disabled by default. Set MIA_REALTIME_ENABLED=true and configure a dedicated MIA_REALTIME_API_KEY as a server secret in an isolated preview. Optional MIA_REALTIME_MODEL defaults to gpt-realtime-2.1. No key is embedded in browser code. No production activation is authorized by this change.

The WebRTC voice conversation is separate from the text conversation and has no booking tools or shared history. No app-side voice transcript is persisted. The provider processes audio. One call per server process, 30-second start cooldown, server hangup after five minutes, client close after 4m30s. In-memory limits are not distributed limits; configure project-level spend controls and durable session management before public release. A failed upstream hangup blocks another call until process recovery or successful retry.

QA: check disabled status and unauthenticated denial, same-origin checks, microphone permission denial, disconnect and mute, interruption, session expiry, text fallback, no false fares/booking claims, and absence of API credentials in network responses. Real provider/browser QA and secret configuration are pending. No live tools until an authorized server-side orchestration layer is implemented.

## Stage 2 functional gate (not a certification)
Cloudflare forwards the dedicated voice key only when the Worker environment is preview and the pilot flag is explicitly true. Leave the flag disabled until an isolated preview with a dedicated provider project is configured. No production keys or production activation. Stop requests now target a per-attempt UUID; cancellation while establishing a call is tracked and the upstream call is closed if it arrives late. An ambiguous upstream connection failure or an invalid call identifier locks the pilot until operator investigation/restart. Verify the provider call is closed before restarting. Limits remain process-local and are not a hard financial cap.

CI regression uses an isolated upstream double and verifies the HTTP route; it is not evidence of audio, provider availability or live latency. For live homologation, use an authenticated preview with a dedicated secret and synthetic, non-personal utterances only. Record commit SHA, preview URL, UTC timestamps, provider model, redacted HTTP status and request/call identifiers, WebRTC ICE/connection state, inbound/outbound RTP packet counts, RTT/jitter/loss and first-audio timing (end of user speech to audible response). Test at least 10 turns per language PT/EN/ES, including interruptions and language switches, microphone denial, network disconnect, stop while connecting, mute, text fallback and expiry. Record actual results and provider usage/cost; never save raw voice or credentials in CI artifacts. Proposed pilot targets: p95 first audio <= 2.5 s, p95 interruption-to-silence <= 500 ms, packet loss < 2% on stable network; these are acceptance proposals, not measurements. Record subjective intelligibility and naturalness using human reviewers. Require all safety and regression checks to pass, then obtain owner authorization before release.
